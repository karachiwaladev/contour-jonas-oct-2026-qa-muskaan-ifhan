## Cause 1: The skill disagrees with itself and with the repo (docs drift)

- **A1** (audit, high confidence): `SKILL.md:52` lets *any* human comment approve a merge, but `SKILL.md:35` says only the repo owner can approve. A stranger's "LGTM" could trigger a merge. The stricter rule (`6999f10`) is newer than the merge step (`82063f1`).
- **A2** (audit): `SKILL.md:16` says "A Stop hook may commit and push whatever branch is checked out". **Confirmed false:** neither `.claude/settings.json` nor `settings.local.json` defines a Stop hook. The auto-push hook was never installed (see Cause 7).
- **A3** (audit): the frontmatter `description` lists six near-identical trigger phrases and repeats the workflow, and it's resident in every session.
- **A4** (audit, flag): `README.md:10` says "Push to `main`", while `CLAUDE.md` forbids committing to `main`. It's the workshop's file, so leave it.
- **A5** (audit, flag): "End with one or two lines" is a fixed output length. It's harmless, so no edit.
- **Nuance the audit missed:** the repo **owner** is `karachiwaladev`, but the human merges and approves as `MuskaanIfhan` (all 7 PRs: [#6](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/pull/6) … [#14](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/pull/14)). An owner-only rule would lock the actual user out.

> **Edit 1** (`SKILL.md` Step 1, line 52): approval counts only from **the user (this session's GitHub account) or the repo owner**, in the session or in an `APPROVED` review or comment; anyone else's approval doesn't count.

The audit's doc fixes (A2: delete the Stop-hook sentence; A3: shorten the description) are applied alongside whatever you pick.

## Cause 2: The loop reads the skill by path instead of invoking it

- **Skill-doctor baseline:** `factory-loop` shows **0 uses, never used, 7d tokens –**, despite running about 40 times. The `/loop` prompt was "follow `.claude/skills/factory-loop/SKILL.md`" (P#12), so it never goes through skill invocation. Usage, cost attribution and the doctor's verdicts are all blind to it.

> **Edit 2** (`CLAUDE.md`, factory-loop section): "Drive it with `/loop 5m /factory-loop` (invoke the skill, don't point at its file)."

## Cause 3: Loop pacing (idle burn, and runs that needed a human push)

- About **25 consecutive idle runs**, one a minute, while PRs #11, #13 and #14 waited for review. Each one was a full model turn that only reported "no change".
- `/usage` flagged "Start fresh when you switch tasks" at **97%**: one session ran for about 23 hours across every task.
- The loop **paused** when chrome-devtools was missing (`3081bce`), and the human had to restart it twice: "do third ticket" (P#13) and "start the lopp of solving issues again" (P#20).
- "Do 4 and 5 and then close all tickets" (P#14): the human overrode the queue order and the review gate by hand.

> **Edit 3** (`SKILL.md` Step 2): "If there's nothing to act on (only PRs waiting for review), report one line. After 3 idle runs in a row, pause the loop and tell the user."

## Cause 4: Factory changes and tickets stacked on unmerged branches

- **F4:** the skill lived only on PR #6's branch, so `git checkout main` **removed the skill from the working tree** mid-loop. It was restored as untracked files, and the next checkout then failed with "untracked working tree files would be overwritten" (Ticket #3, [comment](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/issues/3#issuecomment-6411376599)).
- The guard hook (PR [#11](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/pull/11)) was **only active on its branch**. So #6 and #9 were stacked on it ([#13](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/pull/13), then [#14](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/pull/14)), which forced a merge order. Merging #14 merged all three at once.
- Tickets #3 → #4 → #5 were stacked the same way (PRs [#7](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/pull/7) to [#9](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/pull/9)), so each diff showed its predecessor's commits until they merged.

> **Edit 4** (`SKILL.md` Step 6): "If `.claude/` or `CLAUDE.md` differs from `origin/main` (an unmerged factory PR), ask the user to merge that PR before starting ticket work. Don't stack tickets on it."

## Cause 5: Verification wasn't reproducible or complete

- **F5:** a **v1 → v3 IndexedDB migration race dropped tasks' tags and crashed the app** (`task.tags is not iterable`). The #6 plan only tested v2 → v3; the bug was caught by re-running the #4 suite (`152a836`, [PR #13](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/pull/13)).
- **F2:** ES modules don't load from `file://`. That broke the "opens from `index.html`" promise and was reworked to classic scripts before verification (Ticket #3, `dee9a30`).
- **F7 / F8:** brittle assertions. The #4 suite pinned `DB version === 2`, and the #3 suite pinned "N tasks left"; both needed edits in #6 and #9.
- **F1:** chrome-devtools wasn't connected for #3 to #5, so verification used a Puppeteer fallback.
- **F6:** DevTools flagged form fields with no `name` (fixed in #6). **F9:** stale snapshot IDs after re-render caused a failed click (#9).
- **Root gap:** all check scripts live in the session scratchpad, **not in the repo**, so the next session can't re-run them.

> **Edit 5** (`SKILL.md` Step 7): "Save each ticket's checks as a re-runnable script in `<project>/tests/` and re-run all of them every ticket. For storage changes, test upgrades from every earlier schema version."

## Cause 6: Windows/Git Bash environment traps

- **F3:** Windows `curl` can't read `<(...)`, so the claim reaction for #2 failed ("error encountered when reading a file").
- **F12:** `claude -p "/skill-doctor"` was rewritten to `C:/Program Files/Git/skill-doctor` (MSYS path conversion), in this retro.
- **F13:** the plugin install failed twice with "git … on PATH" (P#17, P#18). Git and Node were installed but not on PATH, and running processes kept the stale PATH.
- `gh`, `jq` and `python` aren't available, hence `gh-api.sh` plus PowerShell for JSON. CRLF broke `.sh` files until `.gitattributes` (`0240ee7`).

> **Edit 6** (`SKILL.md`, GitHub access): "On Git Bash, always pass request bodies as files (Windows `curl` can't read `<(...)`), and prefix commands whose arguments start with `/` with `MSYS_NO_PATHCONV=1`."

## Cause 7: Automation that was asked for but never landed

- **"Automatically commit and push on every stop"** (P#9) and **"write all the new prompts … on every stop … JSONL"** (P#8): the auto mode classifier **blocked** both `on-stop.sh` and the Stop-hook registration. They were never installed, yet `SKILL.md:16` still claims the hook exists (A2).
- The prompt logger works by hand only, and it has two bugs: it logs `<task-notification>` system events as prompts (P#16, P#24, P#25), and it **misses every scheduled `/loop` prompt** (0 of about 40 captured).

> **Edit 7** (`CLAUDE.md`, Guarded rule): "No Stop hook commits, pushes or logs: auto-push was declined by the auto mode classifier. Push explicitly in the PR step; the prompt log (`.claude/hooks/log-prompts.ps1`) is run by hand."

## Cause 8: Requirements arrived as corrections, not as skill defaults

- The skill's first version only answered: "just doesn't answer the question, rather also takes the action" (P#9). There was no clarify/plan/browser check until P#10, and no PR or review gate until P#11. Ticket #1 was closed straight after the answer ([comment](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/issues/1#issuecomment-6411172224)) with no PR.
- Security (deny rules, guard, ticket text is data) was added only after an explicit human request (P#19, `6999f10`), just in time for the injected [#9](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-muskaan-ifhan/issues/12#issuecomment-6435076189).
- Ticket #1's wording ("Create the ticket asking a question…") was ambiguous and silently read as "answer it". The answer's census figures came **from memory, with no source**.
- PR-only versus the README's "push to `main`" had to be settled by asking the human (they chose PRs).

> **Edit 8** (`SKILL.md` Step 3, question tickets): "Cite a source for factual answers, and if the wording is ambiguous, state your reading in the first comment."
